# SQLite、配置一致性与 Windows 运行设计

本文是最终核心版本的存储和运行合同。物理表定义见 [schema.sql](schema.sql)。应用使用一个 Node.js 进程；数据库驱动为 `better-sqlite3`，访问层为 Drizzle ORM。驱动的 Node 原生扩展属于数据库依赖，不承担代理协议处理，也不构成外部代理内核。Caddy 是用户授权的 HTTPS 入口进程，其应用状态与 Node 分别记录。

## 1. 数据库约定

- 数据目录默认是 `C:\ProgramData\NetworkProxy\data`，必须位于本地 NTFS；程序代码和数据目录分开。
- 使用 WAL、`foreign_keys=ON`、`synchronous=FULL` 和 `busy_timeout=20` 毫秒。这些连接级设置在每次打开连接后设置并核验；锁竞争通过事务外有界异步重试处理，不能让同步驱动持续等待一秒。
- `schema.sql` 要求 SQLite 3.38 或更高版本，使用 STRICT 表、JSON 校验、外键、部分索引和递归查询。部署固定 `better-sqlite3` 版本及其内嵌 SQLite 版本。
- 标识符使用稳定 UUID 字符串。名称用于界面和 Clash API 映射，不用名称充当外键。
- 时间为 UTC Unix 毫秒整数；界面按设置的时区展示。
- SQLite 的字节累计字段使用有符号 64 位整数。Node 内部用 `bigint`，兼容 API 的数字转换在序列化边界统一处理；自有 API 对超出安全整数的值使用十进制字符串，Clash API 明确其 JSON 数字精度边界。
- 限额字段 `NULL` 表示不设置该层限制，正整数表示限制；禁用由 `enabled` 表示。不得将 `0` 同时解释为禁用和不限。
- JSON 字段采用确定的版本化 Schema 校验。SQL 的 `json_valid` 只保证合法 JSON，业务层继续校验结构、大小、枚举和秘密引用。

## 2. 表与状态的职责

| 表 | 职责 |
| --- | --- |
| `admin_identity` | 唯一后台管理身份，`id=1`；没有注册或租户模型 |
| `admin_sessions` / `api_tokens` | 后台会话与独立的 Clash、自动化令牌 |
| `credentials` | 自己不同设备或用途的代理凭据，以及固定内部桥接身份与可选限额 |
| `secrets` / `tls_profiles` | 密文秘密、公有证书及私钥引用 |
| `listeners` / `listener_credentials` | 入站监听与凭据授权关系 |
| `subscriptions` | 加密订阅 URL、刷新配置和最近成功状态 |
| `outbounds` / `proxy_group_members` | 节点、组和内置出口的统一身份空间 |
| `route_rules` / `app_settings` | 有序路由与全局配置的编辑投影 |
| `config_revisions` / `runtime_state` | Node 的不可变配置历史与 desired/applied/last-good 指针 |
| `caddy_revisions` / `caddy_revision_secrets` / `caddy_state` | Caddy 的秘密引用模板、引用完整性、应用和恢复指针 |
| `runtime_runs` | 每次进程运行的唯一身份、起止和退出情况 |
| `management_operations` | 异步管理操作的持久阶段、目标 revision 与脱敏结果 |
| `usage_checkpoints` / `usage_totals` / `usage_buckets` | 按运行绝对检查点累积总量和 UTC 小时桶，确保重试不重复统计 |
| `audit_events` / `schema_migrations` | 脱敏操作记录与有校验和的数据库迁移 |

活跃 Socket、认证缓存、并发名额、UDP 关联、目标流、令牌桶、健康状态和当前速率只存在于内存。SQLite 不作为每个连接或每个数据块的计数器。Clash API、自建 Web 和代理模块共享同一份运行时对象。

## 3. 凭据与秘密

后台密码用异步 `scrypt` 校验，保存盐、哈希和固定上限的算法参数。算法参数由程序白名单约束，不能因为数据库中出现异常参数而执行任意规模的内存或 CPU 运算。修改密码递增 `session_epoch`，旧会话立即失效。

会话、Clash secret 和自动化 token 使用高熵随机值；数据库保存 SHA-256 摘要，校验使用固定时间比较。令牌仅在创建时完整显示。需要显式导出时，可另存一份加密秘密，由 `export_secret_id` 引用；普通查询仍不返回完整值。

HTTP/SOCKS 连接密码、SS 密钥和机场认证信息具有客户端导出或协议计算用途，因此保存在 `secrets` 中。它们与后台密码采用不同的存储方式。运行时解密后建立有界认证结构，避免每次代理连接都执行昂贵的密码派生。

`secrets` 使用 AES-256-GCM；每条密文保存唯一的 `(key_version, nonce)`、认证标签和 AAD 版本。AAD 至少绑定 `secretId`、用途与版本。主密钥保存在数据库外的 `master.key`，由运行账户的 NTFS ACL 保护；不写入代码、日志、数据库或普通配置导出。主密钥轮换按批次重新加密，期间同时保留旧、新密钥版本直至校验完成。

配置快照、JSON 设置、订阅展示 URL、Clash metadata 和审计详情只允许秘密引用或脱敏值。应用层递归校验并拒绝在快照中嵌入真实密码、token、私钥和带认证参数的订阅 URL。原始订阅正文不入库；解析后只写规范化节点及秘密引用。

## 4. 入站、节点组与引用完整性

HTTP/SOCKS 凭据通过 `listener_credentials` 授权；一组凭据可绑定多个入口并共享配额。传统 SS 的单密钥入口只能绑定一个有效 SS 凭据；具备明确多用户语义的方法由协议能力注册表校验。SQL 不把任意多个绑定自动解释为协议多用户能力。

`credentials.kind=proxy` 是正常代理凭据，必须包含密码或 SS 密钥。`kind=internal-bridge` 仅用于 Caddy 的固定 `edge-owner` 身份，用户名和两个秘密引用都必须为空；数据库约束禁止普通凭据借此成为无密钥账号。这个身份依然拥有独立 ID、连接与带宽额度，并进入正常连接注册表。

配置验证器只允许 `internal-bridge` 绑定专用 SOCKS5 NOAUTH 桥接入口，且地址必须为 `127.0.0.1` 或显式 `::1`。它不能绑定公共 HTTP/SOCKS/SS 入口，公共入口也不能关闭认证来映射该身份。桥接端口不得经 Windows 端口转发公开。本机 NOAUTH 是对本机进程的信任边界，不能假设 Node 已验证调用方一定是 Caddy。

`listeners` 的唯一索引阻止启用入口使用完全相同的地址和端口。通配地址、IPv4/IPv6 双栈、TCP/UDP 组合、Caddy 对外端口与管理端口之间的重叠，由配置验证器结合实际绑定结果检查。禁用状态不保证该端口将来可以启用。

`outbounds.kind` 将 node/group/builtin 统一起来。`protocol` 保存能力注册表的名称；数据库能保存字符串不表示程序已经支持该协议，只有注册表判定可用且整个传输组合通过校验后才能启用。节点组通过 ID 引用成员；触发器拒绝非组父节点、自引用和间接环。`selected_outbound_id` 的延迟外键确保当前选择属于该组。

修改代理组时，先清除不再存在的选择，再修改成员，最后设置新的选择；在一个事务内完成。成员端点通过删除和插入替换，不能直接更新。节点重命名不改变 ID；Clash URL 中的名称由适配层做编码和查找。

订阅节点以 `(subscription_id, subscription_source_key)` 保持身份；重命名不产生全新 ID。某个订阅暂时失效或删去节点时，先标记不可用并保留现有引用，不级联破坏路由。主动删除被规则、组、入口或订阅抓取路径引用的出口，要求同一次变更提供替代引用。

订阅解压后的响应默认上限是 8 MiB（`8388608` 字节），同时对压缩前响应、解压比例、解析节点数和超时施加限制。数据库中的最大响应设置不替代订阅解析器的全局资源预算。

## 5. 配置版本与应用协调

配置变更进入同一个 `ConfigCoordinator` 串行队列，Web、Clash、订阅刷新和命令行均不能绕过它。请求携带 `expectedRevision`；版本不一致返回冲突。

每次提交创建不可变的规范化快照，其 SHA-256 对稳定序列化结果计算。配置表是当前编辑投影，`config_revisions` 是启动和恢复依据。快照只包含秘密 ID 和公开配置，历史 revision 不复制明文秘密。仍被 last-good 或保留历史引用的秘密不能被垃圾回收。

应用过程为：

1. 构建候选配置，校验引用、能力、规则、组环、限制和资源预算。
2. 准备路由、连接器、解析结构以及能并行预绑定的新监听器；新监听器暂不接受代理流量。
3. 一个短 SQLite 事务写入编辑投影、新 `pending` revision 和 desired 指针。
4. 在一个不跨 `await` 的同步区间替换 Node 运行快照；启动新接入，旧资源进入排空。
5. 更新 applied、last-good 和成功审计。旧配置对象在关联会话结束后释放。
6. 失败时恢复旧运行配置，将候选 revision 标为失败，并恢复 desired；UI 显示失败及目前实际生效的 revision。

数据库事务不能原子覆盖 Socket 生命周期。同地址端口重绑定可能需要短暂停止接入；回滚可以恢复监听，无法复活已经关闭的会话。修改前的配置差异视图必须区分热更新、重新绑定和会话排空。

降并发上限只阻止新的名额申请，默认不踢已有会话；用户显式选择立即执行时才按明确顺序断开。切换代理组默认影响新会话，已建立 TCP 隧道不迁移。禁用凭据默认停止新连接并关闭现有连接；如显式选择保留已认证会话，操作结果和审计必须记录该策略。

## 6. Node 与 Caddy 的应用边界

一个应用配置可生成 Node revision 和 Caddy revision，但两个运行时具有独立的 desired、applied 和 last-good。`caddy_revisions.template_json` 保存本项目内部的版本化模板，认证等敏感字段使用 `secretRef`；它不是可以直接交给 Caddy 的最终配置。`template_sha256` 只覆盖规范化模板，`caddy_revision_secrets` 完整列出模板引用的秘密并保护历史回滚所需的密文。配置验证器检查模板中的所有秘密引用与该关联表完全一致，拒绝明文密码和遗漏引用。

Caddy `basic_auth` 所需的实际值在应用或回滚时才从 `secrets` 解密并仅在内存中渲染，通过受保护的本机管理链路提交。SQLite、revision 快照、审计、日志、诊断导出和持久化配置文件均不得保存这份明文结果。Caddy 自动保存最终配置的功能必须关闭，管理 API 限制在本机可信范围，避免秘密经 Caddy 配置导出或自动保存再次落盘。若使用特定构建无法满足此要求，则配置应用失败并报告原因，不能静默保存明文。

私钥与 ACME 账户材料由 Caddy 独立数据目录保护，不能嵌入数据库快照。Node 根主密钥只保存在数据库外；密文、`secretRef` 与 Caddy 模板均不能包含它。

协调顺序优先准备并验证 Node 新后端，再验证及应用 Caddy 新入口。两边均成功后展示“全部已应用”。Caddy 失败时保留原入口并恢复相应 desired 指针，Node 新资源可回滚或暂时保留为待清理资源，具体结果记录为 degraded。Caddy 已应用但 Node 确认失败时，先恢复 Caddy last-good，防止入口指向不可用后端。

SQLite 提交、Node 内存替换与 Caddy HTTP 管理操作不构成单个事务。每个动作都以 revision 为幂等键记录结果；程序重启后读取实际状态并与记录对照，按 last-good 恢复，不能仅凭上次数据库中的 `ready` 值宣称两个进程仍然健康。

### 异步管理操作

自有 API 返回 `202` 之前，必须提交 `management_operations` 记录。该记录包含稳定 operation ID、类型、目标 Node/Caddy revision、阶段与时间；结果和错误使用经过白名单脱敏的 JSON，不保存请求中的密码、订阅原文、完整 URL token、备份密钥或实际渲染配置。操作阶段转换与对应 revision 指针更新在适用的同一短事务内完成。Web 重连后可从 SQLite 查询结果，不依赖已消失的内存 Promise。

阶段包括 queued、validating、preparing、running、applyingNode、applyingCaddy、verifying，以及 succeeded、failed、rolledBack、requiresRestart、interrupted 终态。终态必须写入结束时间；失败及中断必须包含稳定错误码和可读原因。终态操作不原地重新运行，重试创建新的 operation ID，并关联原目标或新 revision。

进程重启时，测速、备份等需要内存上下文的未完成操作标记为 `interrupted`，不能伪造已完成，也不自动重做可能具有副作用的备份恢复。配置、订阅发布和 reconcile 操作依据其持久目标 revision 与实际 Node/Caddy 状态恢复：确认已成功则补写成功，安全可继续则继续协调，无法确认则回滚或写入失败。缺少持久候选的操作不能从脱敏结果重建秘密。requiresRestart 是已报告的终态；重启后的再次应用使用独立恢复操作，保留原结果。

## 7. 统计检查点的幂等算法

每次 Node 启动生成全新 `runId`。每个统计维度维护从本次运行开始的绝对累计字节数和单调 sequence；持久化的是绝对检查点，而不是需要反复重放的增量。

每批检查点在一个短事务中按主键 UPSERT。触发器执行以下不变量：

- 首次插入，将绝对值计入 `usage_totals`。
- 相同 sequence、相同数值及采样时间的重试不增加累计。
- 新 sequence 仅累加新、旧绝对值之间的差。
- 序号、字节或采样时间回退，或同一序号出现不同内容，直接拒绝。
- 检查点与累计更新处于同一个 SQLite 事务，任一失败均回滚。
- 相同触发器同时将该次新增量写入 `usage_buckets`，因此总量、小时桶和检查点同提交、同回滚。

同一批失败后复用原采样数据和 sequence 重试，不能用相同 sequence 配新的计数。乱序旧批次可在应用层丢弃并记录指标；不能以旧值覆盖新值。避免 `INSERT OR REPLACE`，它会执行删除再插入并破坏幂等累计。

全局、凭据、入口、出口是相互独立的统计视图，不将各维度再次相加得到总流量。计费口径由转发层统一：同一方向的应用负载字节只在一次逻辑边界计数，协议封装流量另设指标。删除节点后累计历史仍保留，因此统计主体不使用会随配置删除而消失的外键。

默认约 5 秒批量落盘，受每批行数和事务时长预算约束；退出时最终 flush。异常终止可能损失尚未落盘的窗口，设计不宣称精确计费。检查点与 totals 不能各自独立清理或重建；维护操作必须保留相应累计关系。归档已经结束的运行时，只删除其不再需要的检查点，保留 totals；不得删除仍有检查点外键的运行记录。

`usage_buckets` 使用 UTC 小时起点作为桶键，按 `(dimension, subject_id, bucket_start)` 唯一，支持 Web 按时间范围和维度查询。`bucket_start = floor(sampled_at / 3600000) * 3600000`。跨小时的单次差额全部归入采样结束时间所在的小时，不做估算拆分；正常至多 5 秒的采样差额因此可能在边界移动至多一个采样周期。锁重试保留原采样时间，不因实际提交延迟改变归桶；事件循环停顿或维护导致采样间隔更长时，仍按结束小时归桶并明确其统计精度，不能称为逐秒精确历史。

小时桶默认保留 90 天，后台以有界批次删除过期桶；累计 totals 独立长期保留。清理历史桶不清除检查点，重复检查点也不会重新增加已删除桶。日、周图表由小时桶查询聚合，界面在本地时区显示，但不将存储桶改成本地夏令时边界。空桶可由查询补零，不能将当前每秒速率误写成历史总流量。

Windows 墙上时钟可能因校时回退。速率和超时始终使用单调时钟；用于检查点的 sampled_at 采用 max(当前 UTC 毫秒, 本 run 上一次样本时间)，保证持久序列不会因小幅校时回退而被拒绝。小时归属按该持久时间计算，时钟异常在状态页报告；不能通过更改已有 sequence 的样本时间来重试。

## 8. 同步数据库与单进程资源预算

`better-sqlite3` 是同步驱动，Drizzle 或外层 `async` 不会使 SQL 离开事件循环。数据访问通过一个小型仓储层执行，预编译语句、有界分页、短事务；转发回调只读内存状态。

每次锁等待最多 20 毫秒。遇到可重试的 `SQLITE_BUSY` / `SQLITE_LOCKED`，先结束或回滚本次事务，再通过异步定时器按约 25/50/100 毫秒加小幅抖动重试，最多四次尝试且总请求期限不超过 1 秒。绝不在持有 SQL 事务时跨 `await`，也不使用同步 sleep。超出预算的配置请求返回明确的数据库繁忙错误；统计保留原绝对检查点并在有界队列中延后重试，不重复记账。单实例模式持续出现锁竞争属于诊断事件，不能靠扩大 `busy_timeout` 掩盖。

在线常规列表限制每页行数，批量写入限制行数；大规模导入先分块解析并让出事件循环，验证成功后进行有界事务提交。审计、统计和订阅状态分别合并批次，不能每个数据包写日志或数据库。每次查询、事务和 checkpoint 都记录耗时指标，超预算触发诊断。

同步备份、完整完整性检查、VACUUM、全库导出和大迁移可能长时间阻塞，必须显式进入维护状态，停止新代理接入并排空现有会话后执行。设计不会把同步备份伪装成后台无影响操作。启动迁移发生在 ready 之前；常规 WAL PASSIVE checkpoint 有频率和大小控制，避免管理请求随意触发重操作。

所有缓存和队列均有数量及字节上限，包括统计批次、日志、慢 WebSocket 客户端、订阅正文、DNS、重放缓存和 UDP 排队。全局会话、握手、上游连接尝试与 UDP 流分别限额。资源预算是配置，不作为未经过 Windows 实测的吞吐承诺。

## 9. 迁移、备份与恢复

`schema.sql` 是可独立验证的新库完整基线，不含伪造的自校验值。生产环境由迁移运行器拥有事务：先在事务外设置并核验 PRAGMA，校验受信任迁移文件的 SHA-256，再将基线中 BEGIN/COMMIT 之间的 DDL 作为初始迁移体执行，写入真实的 `schema_migrations` 记录后一起提交。后续编号迁移文件仅包含迁移体，不再嵌入事务或 PRAGMA。既有迁移的校验和变化即拒绝启动；不得在已存在的数据库上重新执行完整基线，也不能嵌套事务。

迁移前备份；破坏性迁移采用新表、复制、验证、替换，事务提交前检查外键。`PRAGMA foreign_keys` 不在事务中临时关闭。迁移失败不写成功记录，应用停留在维护/错误状态。

WAL 活跃时仅复制 `.db` 不构成一致备份。使用驱动的一致性备份能力；同步实现进入维护并排空后执行。另一种受控方案是停止写入、完成 checkpoint、关闭连接后复制，再重新打开。备份包括数据库、schema 版本、配置 revision、校验和、外部主密钥的独立加密备份，以及需要恢复的 Caddy 数据目录。密钥和数据库备份分开授权。

恢复到临时目录，核验校验和、SQLite 完整性和外键、秘密解密以及配置可用性，再替换活动数据；保留上一份可恢复数据。数据损坏时不自动新建空库覆盖原文件。

## 10. Windows 生命周期

代码固定在只读安装目录，数据目录和 Caddy 数据目录使用明确绝对路径。运行账户有数据读写权限，具有运行所需的最小系统权限。任务计划程序可用于开机启动 Node，设置已有实例运行时不启动新实例及失败重启；Caddy 的托管方式单独记录。

Node 在迁移前取得单实例保护并保持到退出。纯 Node 方案可在固定 loopback 管理/锁定端口建立独占监听；占用即退出，不能先打开数据库并执行迁移再发现第二实例。管理监听启动后保持 not-ready，仅在迁移、秘密和协议监听验证成功后开放正常操作。

停止由受保护的管理命令触发统一排空：停止新代理接入，停止订阅及探活调度，等待会话关闭，达到默认 30 秒期限后销毁剩余会话，最终统计落盘，关闭数据库与日志。Windows 的任务强制终止可能跳过该流程，因此不能只依赖 POSIX 信号或退出回调。Caddy 的停止/继续运行政策单独执行并记录。

启动时将上次没有结束时间的运行记录标记为异常结束；创建新的 `runId`。重新验证 desired 配置并应用，失败时恢复 last-good。实时连接、UDP 关联和名额全部重置，不从旧记录虚构恢复。持久化的 applied 状态只表示上次已应用，启动后必须重新确认。

## 11. 存储与运行验收

1. 空库执行 schema 成功，外键检查无错误；非法布尔、额度、端口、状态和组环被拒绝。
2. 两组并发配置提交只接受正确基准 revision；端口占用失败可回滚并展示实际生效版本。
3. 组成员变更、选择及删除引用受约束，重命名不破坏路由。
4. 同一绝对检查点重复提交不重复计数；新序号只增加差额，旧批次不能覆盖新值。
5. 在事务提交前后分别强制结束进程，累计值一致，连接数重置，应用可恢复。
6. Node 成功/Caddy 失败和 Caddy 成功/Node 确认失败均能按 last-good 恢复，并显示 degraded。
7. WAL 有未 checkpoint 数据时生成的正式备份可独立恢复，秘密可解密。
8. 迁移失败、密钥丢失、数据库损坏或磁盘满时返回明确状态，不以空配置覆盖数据。
9. 慢 WS、订阅大响应、日志风暴和批量数据库操作不产生无界队列；维护操作明确暂停接入。
10. Windows 重启自动启动，一个应用数据目录只有一个 Node 应用实例，正常停止完成排空和最终 flush。
11. 普通代理凭据不能无密钥入库；`internal-bridge` 只映射本机 NOAUTH 的固定 `edge-owner`，公开绑定在配置验证时拒绝。
12. 搜索数据库、备份、Caddy 持久化配置和诊断导出，不能发现 basic_auth 明文或 Node 根主密钥；回滚通过模板与保留的密文引用重新在内存渲染。
13. 数据库被外部连接占锁时，单次同步等待不超过 20 毫秒，重试期间事件循环可以继续服务代理连接，超过期限返回失败。
14. 跨 UTC 小时的检查点仅增加结束小时桶，同一检查点重试不重复增加桶或 totals；清理 90 天前的桶不改变长期累计。
15. 返回 `202` 后结束进程，操作仍可查询；测速/备份变为 interrupted，配置操作依据目标 revision 和实际组件状态恢复，原终态保持不变。
