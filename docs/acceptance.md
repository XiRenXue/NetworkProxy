# 最终核心验收合同

本文定义最终核心版本的完成条件。所有标记为核心必需的功能必须同时通过，不能将其中一部分重新称为可交付核心。条件能力须明确报告可用性，不能仅靠配置导入成功计为支持。

## 1. 验收清单与证据

每次发布保存 release manifest：Windows 版本、Node 精确版本、依赖锁文件 hash、数据库 schema、Caddy/forwardproxy 版本与 hash、目标 Clash 面板版本、各协议参考实现版本、测试结果和未支持能力。

每种协议组合至少使用一个独立实现进行互通，协议规范有向量时还须通过向量。CI 中可以使用参考程序作为测试夹具；生产应用不依赖这些外部内核。

## 2. 协议矩阵

逐项覆盖 protocols.md 的核心入站和出站。每个有意义的入站×出站组合验证 TCP；每个支持 UDP 的组合验证 UDP。HTTP 入口的 TCP 隧道不被错误计作 UDP 能力。

每种组合包括：域名、IPv4、IPv6；随机拆包和粘包；握手后的预读数据；大流量双向传输；认证错误；上游拒绝；拨号超时；对端 reset；半关闭；取消和资源回收。

SS 额外验证认证标签、salt/nonce、密钥派生、重放、数据帧边界、UDP 来源和 SS2022 AES 独立语义。VMess/VLESS/Trojan 的 UDP 必须验证边界、目标和方向，不能用 TCP 页面访问代替。

HTTP/1.1 覆盖普通正向请求、CONNECT、代理认证、IPv6 authority、hop-by-hop 与 Proxy-Authorization 删除、请求/响应流、取消、Upgrade 和 keep-alive。原生 HTTP/2 覆盖一连接多流、单流失败隔离、流关闭释放和 session 关闭清理。

## 3. Caddy h1/h2/h3 最终门槛

1. 固定构建确实包含 forwardproxy，配置可通过其验证。
2. 同一入口分别以 h1、h2、h3 建立真实 CONNECT，经 Node 转发到选定机场；不能只测试管理网站的 HTTP/3。
3. 同一个 h2/QUIC 连接同时打开多个流，Node 按隧道计数和拒绝超限。
4. 普通 HTTP 响应完成、客户端取消、读写错误后，非复用 bridge Socket 和名额及时释放；明确存在复用时，池中连接仍正确占额度并在约定空闲期限内回收，持续重复请求后无单调增长和泄漏。
5. 目标服务器收到的请求不包含外部或内部代理凭据；upstream URL 不携带服务凭据。
6. 域名交给 Node；目标 ACL 和端口策略在 Node 生效；边缘没有绕过 Node 的直连路径。
7. Caddy 停止、重启、reload、Node 不 ready 和 Admin API 超时时的状态与连接行为符合合同。
8. 外部来源无法访问 bridge 和 Admin API。Node 正确标识 bridge 来源，不伪造原始 IP/用户名。
9. UDP/443 被阻断时报告 h3 不可达；HTTP/3 CONNECT 不被宣传为 CONNECT-UDP。

forwardproxy 标记 experimental，以上验证不以 README 功能声明代替。发现模块路径泄漏或凭据传播问题时，选择已包含上游修复且符合合同的构建后才通过；本设计不默认要求新增 Go 开发。

## 4. 配额与资源不变量

- 所有协议共享全局/入口/凭据额度；申请和释放原子、幂等。
- 拨号中的会话占名额，多次重试不额外占用、不重复释放。
- 并发取消、timeout、error、close 各种顺序至少循环 1000 次，不泄漏也不出现负计数。
- HTTP keep-alive、HTTP/2/QUIC 复用、SOCKS UDP 控制连接均遵守其各自计数口径。
- 降低上限、禁用凭据和轮换密钥的行为与设置一致。
- 握手、队列、日志、DNS、重放缓存、UDP 流和 WS 订阅都有硬上限。
- 慢目标、慢客户端、慢面板和突发 UDP 不导致进程内存无限增长。

## 5. 限速与统计

用多个并发连接验证同一凭据共享总上下行额度。大于桶容量的数据块仍可前进；轻流不被大流长期饿死。UDP 超速产生可解释的丢包计数。

已知载荷的上/下行计数一致，协议握手、加密开销与控制探测不重复计入。Web、Clash 和 SQLite 来源相同；Clash 进程累计与跨重启累计区分。

统计 checkpoint 在提交前、提交后和响应丢失位置重试，不重复累计。异常退出误差在声明的未提交窗口内，正常排空后累计完整。

## 6. 路由与 DNS

验证规则顺序、域名匹配边界、CIDR/端口、入口和凭据条件；组环和无效引用被拒绝。只选择满足本次 TCP/UDP/地址族能力的节点。

故障转移只在安全拨号阶段发生，不重放已发送载荷；无匹配上游返回错误且不回落 DIRECT。节点切换影响新连接，旧连接不被假装迁移。

远端解析模式下，Node 不提前解析目标域名；bootstrap 节点解析不形成环。启用 IP 规则解析的影响可观察。Caddy upstream 模式下域名仍到达 Node。

## 7. Web 与 Clash 兼容

固定 yacd 兼容模式及选定 MetaCubeXD 版本，采集其请求和 golden fixtures。验证路径、请求体、字段类型、错误码、WS/token、Origin 和慢消费者，而不仅是能打开页面。

节点列表、真实测速、组选择、连接断开、规则、流量、日志均执行实际操作。未支持字段返回明确错误，不伪造 meta:true 或不存在的扩展能力。连接 start 等易错字段与实际样本一致。

后台完成全部配置、影响预览、保存应用、错误回滚、凭据掩码与显式导出、订阅预览、备份恢复和排空停机。两个界面看到同一个已应用 revision、组选择和连接集合。

## 8. SQLite 与配置故障注入

验证 schema.sql 在空数据库执行，外键与约束有效；迁移校验和与事务正确。多窗口提交以 revision 冲突处理，不能后写覆盖前写。

在验证、端口准备、SQLite pending 提交、Node 发布、Caddy load、ack 超时和 applied 标记各处注入故障。结果必须为已确认成功、明确失败回滚或显式 degraded；不存在“保存成功但入口未知”的隐藏状态。

强制终止后 SQLite 可恢复，不恢复虚假活跃连接。错误 desired 配置按 last-good 策略恢复，并保留失败原因，不无限重启。

活跃 WAL 时生成一致性备份，在独立位置恢复后账号、节点和密钥可用。没有 master.key 的备份不能伪称可恢复敏感配置。磁盘满、只读目录和密钥权限错误有明确状态。

## 9. Windows 稳定性

验证开机自启、专用账户权限、第二实例拒绝、绝对路径、固定端口、防火墙、正确 UDP 广告地址。控制台和管理停止能排空，强制结束后能恢复。

在目标服务器以默认 256 TCP 会话及规定 UDP/WS 负载运行至少 24 小时；记录吞吐、CPU/RSS、事件循环延迟、队列与错误。结束和冷却后不残留 Socket、计时器、名额或无界缓存。不能把此负载要求误写成任意硬件的性能保证。

备份、订阅、日志轮转、配置变更和测速在负载下运行，不能造成无限阻塞。同步 SQLite 操作及批量处理的耗时需纳入报告；超过预算时缩短操作或进入明确维护状态。
